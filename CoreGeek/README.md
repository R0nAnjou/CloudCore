# CoreGeek — 《未来战争》参赛程序

基于官方 Demo `CoreGeek` 骨架重构的参赛程序。
当前策略版本：`central-wall-l3-two-operator-20260924`，第一回合日志打印相同版本号。

## 快速开始

```bash
# 判题器方式启动(比赛环境)
bash run.sh 8080

# 任务状态机回归测试
python -m unittest discover -s tests -p 'test_*.py' -v
```

比赛平台会固定执行 `python main3.py <port>`，因此提交包根目录必须直接包含
`main3.py`。若平台要求上传 tar.gz，压缩包内应是 `CoreGeek/main3.py`。

需要 Python ≥ 3.11, 零第三方依赖(纯标准库)。

## 目录结构

```
CoreGeek/
  main3.py              比赛平台入口: python main3.py <port>
  main.py               服务启动实现
  run.sh                判题器拉起脚本
  src/agent/
    server.py           HTTP 服务: 4s deadline 守卫 + 异常时返回空指令
    protocol.py         协议层: 请求解析 + 全部 12 种动作码构造器
    grid.py             8 向 A* 寻路（含交互目标邻接寻路）+ Bresenham 弹道
    memory.py           跨回合记忆: 建造区试错/新闻日志/SOP 知识库/宝藏线索
    brain.py            主决策编排: 白天分派经济+任务, 夜晚分派防御
    economy.py          经济: 性价比选矿/批量卖矿/建造/升级券/修墙
    defense.py          夜战: 三炮火力分配(火箭群伤/电磁穿透/加特林锥形)+集火超杀转移
    tasks.py            任务引擎: 自进化 SOP 流水线 + LLM 异步 + 宝藏召唤
  tests/
    test_defense_economy.py  首夜建墙/炮台/修复与购物回归测试
    test_task_agent.py  沙盒命令/答案状态机回归测试
    test_survival_loop.py  连续两天出入城、生产、炮台冷却轮换与任务部分提交测试
```

## 已实现能力(对照任务书)

| 模块 | 能力 | 对应得分 |
|---|---|---|
| server.py | 5s/10s 超时保护、空指令安全兜底、HTTP/1.1 | 避免异常淘汰 |
| economy.py | 固定矿工持续采铜铁；建造工批量采石；先形成 3-2-1 火力核心，再用基地升级券回血并补齐三门三级炮 | 经济 + 生存分 |
| defense.py | 火箭选最密落点、电磁穿透弹道、加特林 90° 锥形多目标、伤害预扣集火 | 击杀分 |
| tasks.py | 按路程和历史成功率选任务；查询真实证据→先提交已核实字段争取部分分→继续完善答案；保留返城时间 | 任务分 |
| memory.py | 建造失败位置学习(不再重复违规)、每日新闻存档、SOP 知识库 | 全局 |

## 昼夜循环

- 三座火箭全部布置在基地背敌侧；开拓者守单炮位，建造工守可覆盖两炮的位置，按冷却轮射三炮。
- 正面先建完整 6 格墙，再向两侧各回折 2 格，形成首批 10 面连续 C 墙；三门炮满三级、正面六墙升到二级且留足应急金后，第四天起才扩到 18 面。
- C 墙背面永久保留主通道和维修通道，两个缺口都在严格背敌侧，任何角色进出都不拆墙。
- 固定矿工从开局持续采铜铁；建造工保持“采一批石头→连续建完→再采”的状态，不逐块往返。
- 矿工优先铜铁的往返收益；临近夜晚或卖矿能凑齐升级费用时提前兑现，不为涨价囤货耽误救命资金。
- 用“直达固定炮位”的实际路线估算返程时间；矿工留在墙外生产，建造工和开拓者在最后 5 个白天回合归位。
- 角色移动允许同向跟随已经离开的前一角色，同时拒绝争格和直接换位，避免窄通道中的 A-B-A-B 往返。
- 每回合只为冷却结束、有目标的炮分配控制者。一个角色若同时邻接多座炮，可以跨回合轮换；同时开多炮仍需多个角色。
- 濒危墙先抢修；其余修复利用炮台冷却空窗，两人不会重复使用修复包修同一面墙。
- 只有见过本方机器人浪潮且连续两回合无威胁才进入 `NIGHT_WORK`；浪潮前不对敌方乱开火浪费冷却，清场后开拓者继续任务、建造工购物/升级/修墙、矿工持续生产，空闲炮手优先轰敌方基地。
- 基地低于 50% 时紧急升级；正常成长先建齐三炮并把主火箭升到三级，随后锁定迎敌正中两墙，先一起升二级、再一起升三级；中央双墙未完成前暂停普通成长，完成后再继续到 3-2-1、基地保险和三炮满级。
- 开拓者的查询预算包含返城截止时间；部分答案必须来自成功查询，不猜测缺失字段。

## 本地联调

无官方模拟器时，可运行上面的回归测试；真实联调需判题器或自行
mock：`POST http://localhost:<port>/` 提交仓库 `docs/request.txt` 内容。
入夜前安排角色靠近炮位；一名角色一回合只能操控一座炮。
运行日志中的 `defense round=...` 会记录基地血量、墙数、炮数、金币、石头、
机器人、几何上有人邻接的炮数(`ready_towers`)、实际开火数(`attacks`)、基地等级和累计积分。
`ready_towers` 不保证存在同样数量的独立炮手；`tower` 日志另外记录各炮等级、冷却、控制者与停火原因。
`roles` 记录位置、血量、工作状态，`action_result` 记录购物、出售、升级和建拆墙是否成功。
回归测试验证四角镜像炮位、C 墙永久后门、两炮手轮射、连续清场确认、生产分工和成长顺序；不模拟官方敌人 AI，仍需用正式对战日志继续校准第十夜压力。
